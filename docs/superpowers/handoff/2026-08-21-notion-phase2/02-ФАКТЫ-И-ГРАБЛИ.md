## Изоляция: создать worktree'ы

Это первое, что нужно сделать в новом чате. В tucan обязательно (там незакоммиченная
работа), в остальных — чтобы не переключать ветки под пользователем.

```bash
# бот — часть A (задачи 1–4)
cd /c/active-projects/tucan-bot
git fetch origin main
git worktree add -b feat/landing-cms /c/active-projects/wt-tucan-bot-cms origin/main
cd /c/active-projects/wt-tucan-bot-cms && npm install

# админка — часть B (задачи 5–6)
cd /c/active-projects/tucan
git fetch origin main
git worktree add -b feat/landing-cms /c/active-projects/wt-tucan-cms origin/main
cd /c/active-projects/wt-tucan-cms && npm install   # НЕ npm ci, см. ниже

# лендинг — часть C (задачи 7–11)
cd /c/active-projects/TucanBRAS
git worktree add -b feat/landing-cms /c/active-projects/wt-tucanbras-cms dev
cd /c/active-projects/wt-tucanbras-cms/landing && npm install
```

**В планe пути указаны как основные чекауты** (`cd /c/active-projects/tucan-bot`) — при
работе через worktree подставляйте путь worktree. Это единственное расхождение плана
с реальностью, кроме уже снятого предусловия части C.

> Старые worktree'ы Фазы 1 (`wt-tucan-bot-moderation`, `wt-tucan-moderation`) ещё висят
> в списке `git worktree list`. Они отработали, можно снять: `git worktree remove <путь>`.

## Архитектурные паттерны, которым план следует

**Бот:**
- Контроллеры — классы, экспорт `module.exports = new XxxController()`.
- Ошибки — `next(ApiError.badRequest(...))`, импорт `require('../error/ApiError')`.
- Guard ролей — `checkRole(['ADMIN','OWNER'])` из `middleware/checkRoleMiddleware`.
- Роутеры монтируются в `routes/index.js`, префикс API — `/api`.
- Порт 9000. На старте `sequelize.sync({ alter: { drop: false } })` (`server.js:170`) —
  **любая колонка, которую читает лендинг, обязана быть объявлена в модели, иначе sync её снесёт.**
- Исходящий HTTP — `axios` (уже в зависимостях).

**Админка:**
- Админ-маршруты живут в `src/components/AppRouter.jsx` (массив `authRoutes`), **НЕ в `routes.js`** —
  `routes.js` содержит только часть маршрутов и для админских не используется.
- Карточки разделов — массив `cards` в `AdminOwnerProfile.jsx`.
- HTTP — экземпляр `api` из `src/http/index.js` (axios + JWT из localStorage).

**Лендинг:**
- Пул Postgres — `lib/db.ts`, singleton на `globalThis`.
- Next 16.2.10 App Router, TypeScript strict, Tailwind v4.

## Грабли деплоя

### Админка (tucan) на VPS

```bash
cd /var/www/tucan
git checkout -- package-lock.json   # ОБЯЗАТЕЛЬНО перед pull
git pull
npm install                          # НЕ npm ci
npm run build                        # статику подхватит nginx, pm2 не трогать
```

- **`npm ci` падает**: `package-lock.json` на `main` протух — `Missing: typescript@7.0.2,
  yaml@2.9.0 from lock file` (транзитивные, в `package.json` их нет).
- `npm install` работает, но **каждый раз переписывает лок-файл** → следующий `git pull`
  может отвалиться конфликтом. Отсюда `git checkout --` перед пуллом.
- Однажды стоит пересобрать лок и закоммитить — тогда `npm ci` починится.
- **Фронт tucan — на VPS, не на Vercel.** Это CRA (react-scripts), pm2-процесса у него нет.
- Сервер собирает с **`PUBLIC_URL=/tukanapp/`** (в `.env`, не в гите) → приложение живёт
  на подпути `tucanbras.com/tukanapp/`. Локальная сборка без `.env` даёт `/` — это нормально.

### Лендинг

```bash
cd /var/www/tucanbras-landing && git pull origin main
cd landing && npm ci && npm run build && pm2 restart tucanbras-landing
```

Лендинг на VPS слушает **порт 3001**.

### Бот

```bash
cd /var/www/tucan-bot && git pull && npm install && pm2 restart tucan-bot
```

Грабля: `node_modules` частично отслеживается в этом репозитории.
